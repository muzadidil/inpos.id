INPOS — LAPORAN PEMERIKSAAN & PERBAIKAN BUG
14 Oktober 2026 | Paket Multi-Tenant NestJS + Prisma + MySQL | cPanel

STATUS
Kode sudah diaudit statis dan sejumlah alur frontend diuji secara terisolasi.
BUKAN bukti bahwa semua fitur produksi berjalan. Pengujian NestJS/Prisma ke MySQL asli,
HTTPS/Passenger, pembayaran dan isolasi tenant saat hosting online masih wajib dilakukan.

BUG YANG DIPERBAIKI
1. Produk & Stok: ReferenceError variabel owner di paintProductRows
   yang sebelumnya bisa menghentikan tampilan daftar produk.
2. Produk & Stok: pilihan aktif/nonaktif disediakan pada form tambah/edit;
   produk yang nonaktif diberi penanda dan tidak tampil di kasir / katalog web.
3. Navigasi kasir mobile: akses ke menu lain (Pembelian, Produk, Langganan,
   Karyawan) melalui tombol Menu, tanpa bergantung pada sidebar yang tersembunyi.
4. Navigasi mobile: Home, Pesanan, Transaksi Baru, Laporan, Menu.
   Laporan sementara hanya merangkum sampai 50 penjualan dan 50 pembelian terbaru.
5. Autentikasi: setiap sesi membawa sidik jari hash PIN; sesi lama otomatis
   tidak valid setelah PIN berganti. Endpoint ganti PIN menerbitkan cookie sesi
   dan token CSRF baru agar owner/karyawan/admin bisa tetap melanjutkan.
   SESI LAMA DARI SEBELUM PEMBARUAN KODE INI AKAN PERLU LOGIN ULANG.
6. API: startup menolak placeholder secret berawalan REPLACE_ dan CHANGE_.
7. Akun Karyawan baru diwajibkan ganti PIN saat login pertama.
8. Username registrasi/karyawan lebih ketat; validasi subdomain menolak
   nama dengan tanda '-' di awal/akhir yang tidak valid sebagai DNS label.
9. Transaksi: batas jumlah baris dalam payload dan perlindungan agar stok
   pembelian tidak melebihi rentang INT MySQL.
10. Kasir: pembelian tetap bisa memasukkan barang kosong, tetapi penjualan
    tidak menawarkan stok 0 dan tidak menambah qty melebihi stok tersedia.
11. Kasir: requestId dipertahankan saat pengguna mengulangi transaksi yang
    gagal dengan keranjang sama untuk mengurangi risiko transaksi ganda.
12. Pesanan web: pembatasan tambahan 10 pengiriman/menit per IP
    (untuk mitigasi spam; tidak menggantikan CAPTCHA/WAF bila diperlukan).
13. Pembayaran: kode unik 001–999 dibuat dari sumber acak kriptografis;
    tarif dibatasi pada angka yang aman bagi INT MySQL.
14. PWA Kasir: strategi network-first untuk file shell JS/CSS/HTML,
    cache lama dibersihkan saat service worker versi baru aktif.
15. Form registrasi: teks PIN yang semula menyebut 6 digit dan 8 karakter
    sekaligus sekarang konsisten: PIN 6 digit.

HASIL UJI DI LINGKUNGAN PEMERIKSAAN
- Semua file JavaScript: node --check LULUS.
- 24 file sumber TypeScript: parser TypeScript tanpa kesalahan sintaks.
- Smoke test frontend via sandbox JavaScript: berhasil memuat daftar produk,
  edit dan status aktif, menu mobile, serta retry dengan requestId stabil.
- HTML: ID duplikat tidak ditemukan pada tiga halaman frontend aplikasi.
- Browser headless tidak dapat dipakai karena kebijakan jaringan di sandbox.
- npm install / Nest build / Prisma generate / MySQL end-to-end tidak dapat
  diselesaikan pada sandbox ini. Jangan menyimpulkan backend sudah siap produksi.

KETERBATASAN STARTER YANG BELUM DISELESAIKAN
- Paket ini BELUM berisi semua menu/fitur INPOS HTML terdahulu.
- Multi Satuan menyimpan satuan kemasan dan faktor, tetapi transaksi kasir/
  web toko masih menghitung qty satuan dasar; harga khusus Box/Dus belum ada.
- Laporan di sini hanya ringkasan 50 transaksi terakhir (bukan seluruh periode,
  bukan laporan keuangan/pajak lengkap).
- Belum ada pelaporan Coretax, cetak/PNG struk 58mm, konfirmasi pembayaran
  otomatis, metode pembayaran POS lengkap, laporan keuangan komprehensif,
  barcode scanner lengkap, fitur poin/kupon dan fitur tambahan lain.
- Konfirmasi pesanan Web Toko mengurangi stok tetapi belum membukukan
  transaksi penjualan/pembayaran sebagai Sale.
- Order publik belum menggunakan requestId idempoten: mengirim pesanan
  dua kali dapat membuat dua pesanan; perlu fitur idempotensi di fase berikut.
- Username/WhatsApp untuk login belum lengkap: login backend memakai username.
- Katalog Web Toko menggunakan ikon bawaan, belum ikon/logo per toko.
- Shared hosting tanpa wildcard vhost dan SSL wildcard perlu setup subdomain
  tenant satu per satu atau dukungan teknis dari penyedia hosting.
