PERBAIKAN LANGSUNG
1. Produk/Kasir: pencarian server dan cursor pagination (produk setelah batas awal 500 bisa diakses dengan pencarian); perlindungan hasil pencarian terlambat saat pindah halaman.
2. Web Toko: ambil katalog bertahap 48 item dari server, bukan mengirim 200 item saat membuka toko; hasil pencarian diterima dari server; barang dalam keranjang tidak hilang ketika pencarian berubah.
3. Web Toko: requestId pesanan opsional plus unique (tenantId,requestId) mencegah pencatatan ulang saat client mengirim ulang permintaan yang sama. Client menggunakan requestId yang sama saat retry payload sama.
4. Super Admin: daftar mitra dan tagihan bisa dimuat halaman berikutnya; pencarian mitra berlangsung server-side; respons halaman yang datang terlambat tidak menimpa menu baru.
5. Laporan: total penjualan dan pembelian dihitung dengan agregasi database lintas semua transaksi; tabel riwayat tetap maksimal 50 transaksi terbaru.
6. Kasir: cegah pergantian menu saat checkout berlangsung; tidak merender ulang DOM kasir yang tidak ada setelah operasi asinkron; halaman menu dan modal terlambat dilindungi.
7. Logout: UI tetap login bila logout server gagal (sebelumnya UI menghilang meski cookie bisa tetap berlaku).
8. Validasi: qty pesanan setelah item sama digabung tidak boleh >1000; nominal dan stok produk dibatasi sesuai MySQL INT; form edit satuan kemasan divalidasi seperti form tambah.
9. Database: indeks multi-tenant terarah dan kolom unik requestId pesanan, perlu migrasi sebelum deploy pada database aktif.
10. JS frontend memakai hash versi baru dan PWA cache shell v4 agar browser tidak memuat script lama.

HASIL TES DI LINGKUNGAN INI
- Node.js: sintaks JS node --check.
- TypeScript 24 file: transpile + syntax diagnostics dengan TypeScript 5.8.3, tanpa pemeriksaan tipe lintas dependency.
- Chromium: simulasi UI Kasir, Admin, Web Toko dengan API mock; bukan MySQL asli.
- Integritas arsip: akan diverifikasi saat pengepakan ZIP.

YANG MASIH PERLU DIUJI/DIKEMBANGKAN
- Typecheck (`npm run typecheck`) setelah npm install + prisma generate pada server.
- Migrasi SQL dan transaksi NestJS/MySQL cPanel riil, uji keamanan dan uji load.
- Password/PIN 6 digit: tetap perlu antibruteforce berbasis identitas dan pemantauan IP/proxy yang benar.
- Prefix wildcard hosting dan SSL bukan ditangani oleh kode.
- MySQL LIKE contains tidak otomatis efisien untuk jutaan baris; untuk skala tersebut desain pencarian fulltext tersendiri.
- Konfirmasi pesanan Web Toko belum otomatis masuk laporan penjualan.
- QRIS kode 001–999 masih dapat habis pada banyak tagihan menunggu; fitur verifikasi masih manual.
- Multi Satuan masih metadata dan belum mendukung harga khusus Box/Dus pada transaksi.
- Fitur lengkap INPOS HTML lama belum seluruhnya tersedia dalam starter multi-tenant.

PERINGATAN: Backup sebelum migrasi, uji pada staging, jangan menjalankan prisma db push secara sembarangan pada database lama yang berisi data.
